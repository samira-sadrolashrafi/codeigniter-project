# افزوده شدن نام و نام خانوادگی به ثبت‌نام

این بسته براساس نسخه `codeigniter_project_recovery_full.zip` تهیه شده است؛ بازیابی رمز عبور و محدودکننده تلاش ورود نسخه قبلی را حفظ می‌کند.

## رفتار جدید

- در ثبت‌نام، `first_name` (نام) و `last_name` (نام خانوادگی) **الزامی** هستند.
- نام و نام خانوادگی **Unique نیستند**؛ امکان ثبت یک نام برای کاربران مختلف وجود دارد.
- `username` مانند قبل **Unique** است؛ هم پیش از ثبت‌نام بررسی می‌شود و هم قید `uq_users_username` در دیتابیس از تکرار جلوگیری می‌کند.
- `email` نیز مانند قبل Unique باقی مانده است. ورود همچنان با **نام کاربری و رمز عبور** انجام می‌شود، نه نام واقعی.
- فیلدهای نام فارسی، انگلیسی، ترکیبات دارای فاصله، نیم‌فاصله، خط تیره و آپاستروف را می‌پذیرند، حداکثر ۱۰۰ نویسه.
- برای کاربران ثبت‌شده قبلی، دو ستون جدید در دیتابیس Nullable هستند تا مهاجرت باعث از دست رفتن حساب‌های قبلی نشود.
- این تغییر نام و نام خانوادگی را تنها در ثبت‌نام ذخیره می‌کند؛ قابلیت ویرایش پروفایل یا نمایش نام کامل در هدر اضافه نشده است.

## روش نصب

**قبل از نصب از دیتابیس و سورس فعلی نسخه پشتیبان بگیرید.**

### روش ۱: جایگزین کردن نسخه کامل

محتوای `codeigniter_project_names_full.zip` را استخراج و به جای پروژه نسخه قبلی قرار دهید. در صورتی که پس از دریافت بسته قبلی، فایل‌ها را خودتان ویرایش کرده‌اید، روش پچ را ترجیح دهید تا آن تغییرات از بین نروند.

### روش ۲: فقط اعمال تغییرات

فایل‌های داخل `codeigniter_name_fields_patch.zip` را **نسبت به ریشه پروژه** کپی کنید. این پچ بر پایه نسخه قبلی دارای بازیابی رمز عبور تهیه شده است، نه نسخه اولیه GitHub. فایل `recovery_questions.php` در این پچ دستکاری نشده است.

### اجرای Migration

از پوشه‌ای که `compose.yml` قرار دارد:

```bash
docker compose up -d
docker compose exec codeigniter-dev-environment php index.php migrate
```

Migration `008_add_user_names.php`، ستون‌های `users.first_name` و `users.last_name` را اضافه می‌کند، و `migration_version` از ۷ به ۸ ارتقا یافته است. در صورت نصب تازه، Migrationهای ۱ تا ۸ باید اجرا شوند. **Migration شماره ۱ را دستکاری نکرده‌ایم** تا دیتابیس‌های قبلی حفظ شوند.

برای تأیید ساختار جدول در MariaDB:

```sql
SHOW COLUMNS FROM users LIKE 'first_name';
SHOW COLUMNS FROM users LIKE 'last_name';
SHOW INDEX FROM users WHERE Key_name = 'uq_users_username';
```

## تست دستی

1. فرم `/register` را باز کنید: «نام»، «نام خانوادگی»، «نام کاربری» و سایر فیلدها باید نمایش داده شوند.
2. با `first_name=علی`، `last_name=رضایی`، `username=ali_01` ثبت‌نام کنید (ایمیل متفاوت و معتبر، رمز و سؤال امنیتی معتبر).
3. کاربر دیگری با **همان نام و نام خانوادگی** و `username=ali_02` و ایمیل دوم ثبت کنید: باید موفق باشد.
4. مجدداً با `username=ali_01` ثبت‌نام کنید: باید پیام «این نام کاربری قبلا انتخاب شده است.» و HTTP 422 دریافت کنید.
5. نام یا نام خانوادگی را خالی بگذارید: باید HTTP 422 و خطای مربوط به همان فیلد نمایش داده شود.
6. با کاربر قدیمی وارد شوید: ورود باید بدون نیاز به تنظیم نام کار کند.
7. بررسی کنید دو نام در دیتابیس ذخیره شده‌اند:

```sql
SELECT id, first_name, last_name, username, email FROM users ORDER BY id DESC LIMIT 10;
```

## فایل‌های تغییر کرده

- `src/application/views/auth/register.php` — فرم دو فیلدی واکنش‌گرا
- `src/assets/js/auth.js` — نمایش خطای اعتبارسنجی هر دو فیلد
- `src/application/controllers/Auth_api.php` — دریافت و اعتبارسنجی داده‌ها و خطای 422
- `src/application/services/Auth_service.php` — ذخیره هر دو مقدار همراه کاربر
- `src/application/helpers/validation_helper.php` — اعتبارسنجی امن رشته‌های نام
- `src/application/config/migration.php` — ارتقای نسخه Migration به ۸
- `src/application/migrations/008_add_user_names.php` — دو ستون nullable جدید بدون UNIQUE

## محدوده اعتبارسنجی انجام‌شده

تمام فایل‌های PHP برنامه با `php -l` و همه فایل‌های JavaScript با `node --check` از نظر Syntax بررسی شدند. علاوه بر آن، اعتبارسنجی نام روی نمونه‌های فارسی/انگلیسی و ورودی نامعتبر اجرا شده است. اجرای کامل با سرویس MariaDB و تست ثبت‌نام واقعی در مرورگر انجام نشده و نیازمند محیط محلی شماست.

**نکته:** سؤال‌های امنیتی نسخه کامل همان سؤال‌های نسخه قبلی هستند. اگر قبلاً آن‌ها را به‌صورت دستی تغییر داده‌اید، برای حفظ تغییراتتان فقط پچ نام و نام خانوادگی را اعمال کنید.
